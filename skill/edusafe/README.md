# 에듀세이프 (EduSafe) 자가점검 스킬

교사가 만든 교육용 앱을 **자기 컴퓨터에서, 자기 구독으로** 배포 전에 점검하는 스킬입니다. 개인정보 보호법과 안전성 확보조치 기준을 기준으로 무엇을 고쳐야 하는지 근거와 함께 알려 줍니다.

- **버전**: `rules/version.json` 의 `edusafe_version` 이 정본입니다.
- **필요한 것**: Claude Code 또는 Codex CLI. Node 18+ 가 있으면 결정적 스캔이 돌고, 없으면 기능이 줄어든 채로 실행됩니다.
- **설치할 의존성 없음**: `npm install` 이 필요 없습니다. 스킬 폴더는 Node 내장 모듈만 씁니다.

## 설치

압축을 풀어 나온 `edusafe` 폴더를 **통째로** 아래 위치에 놓고, 도구를 새로 실행하면 인식됩니다.

| 도구 | 놓을 위치 | 부르는 법 |
|---|---|---|
| Claude Code | `~/.claude/skills/edusafe/` | `/edusafe` |
| Claude Code (Windows) | `%USERPROFILE%\.claude\skills\edusafe\` | `/edusafe` |
| Codex CLI | `~/.agents/skills/edusafe/` | `$edusafe` 또는 `/skills` 에서 선택 |
| Codex CLI (Windows) | `%USERPROFILE%\.agents\skills\edusafe\` | `$edusafe` |

폴더 안에 `SKILL.md` 가 바로 보여야 합니다. `edusafe/edusafe/SKILL.md` 처럼 한 겹 더 들어가 있으면 인식되지 않습니다.

## 사용

점검할 앱의 폴더에서 도구를 열고 `/edusafe` (Codex 는 `$edusafe`) 라고 하면 됩니다. 나머지는 스킬이 순서대로 진행합니다.

결과는 앱 폴더 안에 생깁니다.

```
<앱 폴더>/edusafe-report/
 ├─ edusafe-report.html      ← 이 파일을 브라우저로 여세요
 ├─ edusafe-report.json
 ├─ edusafe-report.md
 ├─ scan.json
 └─ history/                 ← 직전 실행 결과, 최대 5개까지 보관
```

`edusafe-report.html` 은 인터넷 연결 없이 열리는 한 장짜리 파일입니다. 자바스크립트가 없고 외부에서 아무것도 불러오지 않습니다. 인쇄·PDF 저장할 때 접어 둔 내용을 모두 펼칠지 고를 수 있어, 학교운영위원회 제출 자료로 그대로 쓸 수 있습니다.

### 알아 두면 좋은 것

- **검사는 파일과 git 기록만 읽습니다.** 운영 중인 서비스에 요청을 보내거나 데이터를 쓰지 않습니다.
- **코드를 고치지 않습니다.** 수정을 원하시면 보고서를 본 뒤 "R-secrets 고쳐줘"처럼 따로 요청하세요. 그건 별도 작업입니다.
- **점수를 매기지 않습니다.** "반드시 수정 / 권장 / 참고 / 판단불가 / 교사 확인" 다섯 줄로만 알려 드립니다.
- **판단불가가 나오는 건 정상입니다.** 코드만으로는 알 수 없는 것이 있습니다. 스킬이 물어보면 답해 주시면 그만큼 줄어듭니다.

### 빌드를 실행할지 물어볼 때

번들 파일에 키가 들어갔는지 보려면 빌드 결과물이 필요합니다. 그래서 실행 중에 이런 화면이 나올 수 있습니다.

> 빌드 스크립트와 의존성은 임의 코드를 실행할 수 있고 이 컴퓨터의 환경변수·토큰에 접근할 수 있습니다.

**본인이 만든 앱이 맞고 의존성을 신뢰할 때만 승인하세요.** 건너뛰어도 보고서는 나옵니다. 빌드가 필요했던 항목만 "판단불가"로 남습니다.

### 기록 지우기

`edusafe-report/` 폴더를 통째로 지우면 됩니다. `history/` 안의 지난 기록도 함께 사라집니다.

### `.gitignore` 권고

보고서에는 코드 인용과 교사 답변이 들어갑니다. 저장소에 올리지 않으시려면 `.gitignore` 에 한 줄 추가하세요.

```
edusafe-report/
```

스킬이 0단계에서 이 줄이 있는지 확인하고 없으면 권고합니다. 강제하지는 않습니다.

## 이 보고서가 무엇이 아닌지

> **이 보고서는 거울이지 증명서가 아닙니다 — 인증은 교육청 심사에서 코드를 직접 재검사합니다.**

이 스킬은 선생님 컴퓨터에서 선생님 권한으로 도는 평범한 파일입니다. 항목을 지우거나 보고서를 편집하는 것을 막을 방법이 없습니다. 그래서 이 산출물은 **인증 증거가 아닙니다.**

보고서에 남는 지문(스킬 지문·파일 해시·git SHA)은 변조 방지 장치가 아니라 **우발적인 수정을 드러내기 위한 대조 자료**입니다.

## 남의 코드에는 쓰지 마세요

**이 스킬을 다른 사람의 저장소에 그대로 쓰지 마세요.** 이 스킬은 "내가 만든 앱을 내가 점검한다"를 전제로 만들어졌습니다. 빌드 실행 승인, git 히스토리 전수 스캔, 시크릿 인용 같은 동작은 그 전제 위에서만 적절합니다.

남의 코드를 점검해야 한다면 그 코드의 주인에게 이 스킬을 안내해 직접 돌리게 하세요.

## 무엇을 점검하나

8개 카테고리 37개 항목입니다.

| 카테고리 | 무엇을 묻나 |
|---|---|
| 1. 수집 | 무엇을 모으나 |
| 2. 접근·권한 | 누가 무엇을 할 수 있나 |
| 3. 비밀·파일 노출 | 저장소·번들·히스토리에 뭐가 들어 있나 |
| 4. 제3자 전송·추적 | 데이터가 어디로 나가나 |
| 5. 화면·로그 노출 | 눈에 어디까지 보이나 |
| 6. 코드 안전 | |
| 7. 고지·보유·파기 | 알리고, 지키고, 지우나 |
| 8. 학생 안전 | |

항목마다 법령·고시·안내서의 근거를 조항 단위로 달아 두었습니다. 자세한 목록은 `rules/items.json` 에 있습니다.

## 정식 지원 스택

HTML/JS · React/Vite · Next.js 에 Firebase 또는 Supabase 를 붙인 구성을 정식 지원합니다. 그 밖의 스택에서는 스택과 무관한 항목만 판정하고, 스택 특화 항목은 "판단불가(미지원 스택)"로 남습니다.
