## Step 1 — 설치 ✅

`edusafe/` 를 `~/.claude/skills/edusafe/` 에 복사했다.

- 파일 11개가 전부 복사됐다.
- **설치본의 지문이 배포본과 일치한다**: `sha256:da7c4ee9…` (원본 = 설치본).
- Claude Code 가 재시작 없이 스킬을 인식했다 — 실행 중인 세션의 사용 가능 목록에 `edusafe` 가 나타났다. README 의 "도구를 새로 실행하면 인식됩니다" 는 보수적인 안내이고, 실제로는 더 빨리 잡힌다.

## Step 2 — 픽스처 대화형 ❌ 미수행

수행하지 못했다. 이유: 마감(2026-08-29) 시간 부족. 대화형 실행은 사람이 승인·답변해야 하는데, 그 시간을 실제 앱(Step 6)에 쓰기로 결정했다.

## Step 3 — 비대화형 (출시 게이트, REQ-12.7) ❌ 미수행

**두 번 시도했고 두 번 다 완주하지 못했다. 스킬이 멈춰서가 아니라 검증을 중단해서다.** 게이트 통과로도 실패로도 기록할 수 없다.

### 1회차 — 검증 도구의 타임아웃

```
claude -p "/edusafe" --allowedTools "Bash(node *)" "Bash(git *)" Read Write Glob Grep
```

| 시각 | 사건 |
|---|---|
| 00:34:09 | 시작 |
| 00:35:24 | `edusafe-report/.staging-429315623/` 생성 — 0단계 통과 |
| 00:35:25 | `scan.json` 9,627 bytes — **1단계 결정적 스캔이 실제로 돌았다** |
| 00:35:25 ~ 00:49:09 | 산출물 없음 (13.7분) |
| 00:49:09 | 래퍼의 15분 타임아웃이 SIGKILL |

보고서 4파일은 나오지 않았다. 15분은 spec 이 정한 값이 아니라 검증 래퍼에 임의로 넣은 값이다(spec 은 git 히스토리 120초, 빌드 10분만 규정한다).

### 2회차 — 관측을 붙였고, 원인이 보였다

1회차는 `-p` 기본 출력이 **끝나야 한 번에 나오는** 탓에 "멈춘 것"과 "일하는 중"을 구별할 수 없었다. `--output-format stream-json --verbose` 로 다시 돌리자 4분 30초 동안 도구 호출 27번이 보였고, 그 대부분이 이것이었다:

```
Read: rules/items.json          Read: rules/session.json
Read: rules/moe-checklist.json  Read: rules/report.contract.json
Read: rules/scan-rules.mjs      Bash: node -e "…"  × 5
```

**에이전트가 판정을 시작하기 전에 스킬 자신의 규칙 데이터를 통째로 읽고 있었다.** 항목 37개·하위 점검 134개·규칙 48개·계약 131행이 전부 판정 전에 컨텍스트에 들어가야 하는 구조다. 1회차의 13.7분도 대부분 이것이었을 가능성이 크다.

이건 스킬이 멈춘 것이 아니라 **설계상 무거운 것**이다. 다만 확인된 사실은 아니다 — 2회차도 완주 전에 중단했다.

### 남은 위험

이 게이트가 닫히지 않은 채로는 다음을 모른다.

1. 4~6단계가 사람 없이 끝까지 가는지
2. `coverage.build` 가 `{skipped, non-interactive}` 로 기록되는지
3. `coverage.evidence`·`coverage.teacher` 가 `skipped` 이고도 보고서가 완성되는지
4. 비대화형 판정 수치가 대화형과 같은지

**출시 판단**: REQ-12.7 이 이것을 출시 게이트라고 못박았으므로, 이 배포본은 **게이트를 통과하지 못한 상태**다. 그 사실을 안내 페이지나 README 에서 숨기지 않는다.

## Step 7 — 발견된 결함

### D-1. 계획서가 존재하지 않는 CLI 플래그를 지시했다

| | |
|---|---|
| 분류 | **문서가 틀렸다** |
| 내용 | Task 9 Step 3 이 `claude -p "/edusafe" --cwd <픽스처 경로>` 라고 지시하는데, `--cwd` 플래그는 claude 2.1.216 에 없다. |
| 조치 | 계획서를 먼저 고쳤다. 작업 디렉터리는 프로세스의 cwd 로 정해진다는 것과, 관측을 위해 `--output-format stream-json` 이 필요하다는 것, 스캔·렌더가 node 로 도는 만큼 `Bash(node *)` 허용이 필요하다는 것을 함께 적었다. |

### D-2. 계약에 없는 파일이 `edusafe-report/` 에 생긴다

| | |
|---|---|
| 분류 | 관찰 — 원인 미확정 |

| 다음 | 절차서가 staging 경로를 어떻게 들고 다닐지 명시하지 않은 것이 원인일 수 있다. 완주한 실행에서 확인한 뒤 판단한다. |
